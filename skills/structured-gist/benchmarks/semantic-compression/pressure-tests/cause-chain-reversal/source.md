The checkout outage started at 14:02 and the first signal on-call saw was a wave of database connection errors from the payments service. Because connection errors were the first thing visible in the logs, the initial theory was that the database's connection pool had simply been exhausted by traffic, and on-call spent the first twenty minutes operating on that assumption. As a stopgap, the connection pool size was raised from 50 to 150 at 14:24, and error rates did drop noticeably afterward, which at the time felt like confirmation that pool exhaustion was in fact the root cause.

Error rates were not fully back to normal, though, and a slower secondary investigation kept going in parallel. That investigation pulled query-level tracing from the same window and found that one specific query, used by the payments service to look up a customer's order history, was taking upward of eight seconds per call instead of its usual under-100-millisecond time. Every one of those slow calls held a database connection open for the full duration, and under load that was enough connections tied up simultaneously to starve everything else — which is what actually produced the pool-exhaustion symptoms on-call had been treating as the root cause.

The slow query itself was traced to a schema migration that had shipped two days earlier and had silently dropped an index the query depended on. So the real root cause was that missing index, not the connection pool: the pool exhaustion was a downstream symptom of the slow query, and the slow query was a downstream symptom of the migration. Raising the pool size to 150 had only bought headroom — it reduced how often the symptom surfaced, but it did nothing to fix the query itself, and the same slow-query behavior kept recurring under peak load. The actual fix landed later that day: adding the missing index back, which brought the query back under 100 milliseconds and eliminated the connection pileup entirely. The pool size was left at 150 afterward since there was no reason to revert it, but the team's postmortem was explicit that the pool increase was never the fix — the index was.
