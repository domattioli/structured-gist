Spent this session chasing down why newly-added skills never showed up for consumer repos. The install flow, `load_local_skills`, was written to look for a manifest at `.claude/skills.manifest.json` and to expect skill directories under `.claude/skills/`. But this repo actually keeps its skills at the top level, in `skills/`, not under a `.claude/` prefix at all. Because the paths never matched, nothing ever got symlinked into `~/.claude/skills/`, and the harness only scans `~/.claude/skills/` once at startup — there is no hot reload — so a skill that missed the initial scan simply never appeared for the rest of the session, no matter how long you waited.

The fix walks the repo for every `skills/<name>/SKILL.md`, capping the search at `maxdepth 2` so fixture directories nested deeper under `tests/fixtures/` don't get mistaken for real skills. Each match gets its frontmatter validated before anything else happens. Only after that does the script symlink the skill directory into `~/.claude/skills/`, skipping any name that's already linked rather than clobbering it. As a last step it walks every link it just created and confirms the symlink resolves and that the target's version field actually parses, so a broken link fails loudly instead of silently.

With the fix in place, all 77 skills load at session start, and any consumer repo now picks up skill updates automatically the next time it bootstraps a session, with no manual resync step required.
