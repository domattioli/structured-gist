Spent this session digging through structured-gist's own benchmark history to figure out what has actually been measured versus what has only ever been asserted. The original primary metric was `seconds_to_locate_fact`, wall-clock time for a reader to find a single fact by scanning an outline versus reading prose end to end. It sounded like the right metric, but across six separate version bumps it was never once measured — every historical row that cited it reads "not-measured" or "n/a." Because of that track record, the metric was formally retired on 2026-07-03 and replaced with `word_count_reduction_pct` as the declared primary benchmark, specifically because that was the only metric the project's history had ever recorded a real number for. The v0.2.9 row backs this up directly: a 147-word dense paragraph became an 88-word outline over the same matched scope, a 40.1% reduction, computed with a literal word count rather than estimated.

Later, v0.4.0 introduced a more ambitious three-axis benchmark called `outline_quality_composite`, combining retention, robustness, and brevity, under spec-023. It compared the normal direct-prompt outline mode against an experimental knowledge-graph generation mode, called KG mode, across a 20-source corpus. Direct-prompt mode scored a composite of 0.5488. KG mode scored higher overall at 0.7604, and its robustness score was a perfect 1.0 by construction, since KG mode enforces structure mechanically. But KG mode's retention score, 0.7608, was noticeably lower than direct-prompt's 0.8285, because KG mode's stricter word budgets ended up dropping real content. The recorded verdict was "iterate," not "ship" — KG mode never became the default rendering path, and it was later explicitly excluded from the public-facing scaffold of this repository under spec-026's FR-006.

The more surprising discovery was that the actual scoring machinery behind that v0.4.0 row, the `compare_corpus.py` and `score_outline.py` scripts along with the 20-source corpus that fed them, does not exist anywhere in this checkout. Those lived in a private upstream repository, and a series of "sync from DomI structured-gist skill" commits stripped them out when this public scaffold was built, leaving only tiny non-functional placeholder stub files and the historical benchmark.md row as the sole surviving evidence that the measurement ever happened.

Two earlier scoring approaches were explored and abandoned before that composite was built. "SCU scoring," short for semantic content-unit scoring, compared outline quality against source text unit by unit, but it was never formalized into a repeatable benchmark anyone could rerun. Separately, a JSONL claim-list output format was tested as a possible replacement for the tree-shaped outline itself, and it was rejected outright because its recall dropped below the acceptance threshold the team had set.

One question is still sitting open from this archaeology: now that a real retention-scoring approach exists, should KG mode be revisited, or does its retention gap make that a dead end regardless of how good its structural robustness is?
