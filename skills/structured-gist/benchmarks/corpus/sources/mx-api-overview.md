The public API exposes three resource families: projects, datasets, and jobs. Projects are the billing and permission boundary; every other resource belongs to exactly one project. Datasets hold versioned tabular data, and every write creates a new immutable version rather than mutating in place. Jobs are asynchronous operations over datasets, such as imports, exports, and transformations. Authentication uses scoped tokens. A token carries a project identifier, a role, and an expiry, and the role is one of reader, writer, or admin. Readers can list and download. Writers can additionally create dataset versions and submit jobs. Admins can manage tokens and delete resources. Tokens expire after at most ninety days and the API returns a distinct error code, 4012, in the week before expiry so that clients can rotate proactively. Three behaviors trip up new integrators. Rate limits are per token, not per project, so parallel workers sharing one token throttle each other; issue one token per worker. Job submission is idempotent only if the client supplies an idempotency key, and retries without one create duplicate jobs. And dataset version numbers are not guaranteed contiguous, because failed writes consume a version number; clients must treat versions as opaque ordered identifiers, never compute arithmetic on them. The deprecation policy: endpoints are announced as deprecated at least 180 days before removal, deprecated endpoints return a warning header on every response, and the changelog feed carries a machine-readable deprecation notice from day one of the window.
