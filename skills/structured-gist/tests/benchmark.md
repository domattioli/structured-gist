# Benchmark — `structured-gist`

> Generated from `templates/benchmark.md.tmpl` (mandate per this repo , 2026-05-18).
> Every version bump in `MANIFEST.md` must add a row here justifying the bump with a measured delta.

## Metric

`word_count_reduction_pct` — percentage reduction in word count between an equivalent-content dense paragraph and its structured-gist outline rendering (same matched scope, computed directly via word count — not estimated). Higher magnitude is better. Secondary: `user_reask_rate_on_explanations` — fraction of explanatory answers that draw a "restructure / re-explain" follow-up. Lower is better.

**Retired 2026-07-03 ():** the original primary metric, `seconds_to_locate_fact` (wall-clock seconds for the user to locate a single requested fact by scanning structure vs. reading prose end-to-end), was never once measured across 6 version bumps — every historical row below that cited it reads "not-measured" or "n/a." `word_count_reduction_pct` replaces it as primary because it's the only metric this skill's history has ever actually recorded a real number for (v0.2.9: -40.1%; v0.2.10: skim/standard/deep word counts). `seconds_to_locate_fact` remains in the historical rows below unedited (accurate record of what was attempted at the time), but is no longer this skill's declared benchmark.

## Measurement protocol

- **Fixture:** `skills/structured-gist/examples/self-explain.md` (same-content before/after) + `examples/{skim,standard,deep}.md` (granularity-ladder word counts).
- **Procedure:** write the same content as (a) a dense prose paragraph and (b) a structured-gist outline (skim/standard/deep as relevant); count words in each with a direct word count (e.g. `python3 -c` or `wc -w` on matched-scope text); record the delta. For the secondary metric, count restructure-requests per N explanatory answers across sessions.
- **Sample size:** every version-bump row below is one measured pair; ≥30 explanatory answers for the secondary metric.

## Live measurement (real API, output-token savings)

Structured like the [caveman benchmark harness](https://github.com/JuliusBrussee/caveman/tree/main/benchmarks): `../benchmarks/{prompts.json,run.py,requirements.txt}` calls the real Anthropic API twice per prompt (plain prose vs. `structured-gist` structured output, same model, same `max_tokens`) and measures actual `usage.output_tokens` — not a character-count estimate. `run.py` loads `../SKILL.md` fresh off disk as the structured-gist system prompt each run, so this always measures the currently shipped skill, never a duplicated/stale copy of its rules. See `../benchmarks/run.py --help`; `--dry-run` previews config with zero API calls. Requires `ANTHROPIC_API_KEY` + open egress to `api.anthropic.com` — not available in every sandboxed session (this repo's own container blocks it; run from an user machine or an open-egress runner, same pattern as ``'s corpus-refresh protocol).
